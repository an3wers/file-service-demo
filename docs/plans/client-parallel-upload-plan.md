# Параллельная загрузка файлов и безопасный повтор

Статус: спецификация целиком подтверждена пользователем. Изменения реализации ещё
не внесены.

Опубликована как [GitHub issue #36](https://github.com/an3wers/file-service-demo/issues/36)
с меткой `ready-for-agent`.

Доменный язык — в [CONTEXT.md](../../CONTEXT.md), архитектурное решение о повторе —
в [ADR-0008](../adr/0008-povtor-zagruzki-bez-dublikatov.md).

## Согласованные решения

- Пользователь выбирает несколько файлов в проводнике. Загрузка начинается только
  после нажатия общей кнопки «Загрузить».
- У каждого файла собственные прогресс, отмена, ошибка и результат. Ошибка одного
  файла не останавливает остальные загрузки.
- Для выбранных файлов общие режим загрузки и каталог назначения. Настройки
  фиксируются при запуске; последующая навигация не меняет назначение файлов.
- Одновременно выполняются не более трёх загрузок файлов. Остальные ожидают
  свободного места; ожидающую загрузку можно отменить.
- Закрытие модалки не прерывает загрузки. В основном интерфейсе доступен способ
  снова открыть прогресс загрузок.
- Пользователь сам открывает и закрывает модалку, в том числе после завершения
  всех загрузок. Автоматического закрытия при успехе нет.
- Каждый успешно подтверждённый файл сразу становится доступен в основном списке
  своего каталога. Завершение загрузки не переключает текущий каталог пользователя.
- Дополнительный выбор дополняет список, а не заменяет его. Новые файлы ожидают
  отдельного нажатия «Загрузить». Пока есть активные или ожидающие загрузки, общие
  режим и каталог фиксированы также для последующих добавлений.
- До запуска файл можно убрать из модалки; ожидающую или активную загрузку можно
  отменить. Отмена оставляет строку с результатом «Отменено».
- Удаление успешно загруженного файла из модалки означает удаление самого файла
  из файлового хранилища, а не только строки. Строки с ошибкой или отменой можно убрать.
- Для файлов с ошибкой нужна кнопка «Повторить». Исправимая ошибка передачи приводит
  к новой попытке передачи; ошибка подтверждения — к повтору подтверждения того же
  файла, чтобы не создавать дубликат.
- В текущую итерацию запрещён повторный выбор файла с тем же полным именем,
  включающим расширение, и размером. Время изменения не учитывается. Удаление строки
  не снимает запрет до конца текущей итерации.
- Итерация начинается с первого выбора и заканчивается, когда все выбранные файлы
  загружены, отменены, убраны или завершились ошибкой. Неотправленные файлы удерживают
  её открытой; закрытие модалки её не завершает. Следующий выбор после завершения
  начинает новую итерацию, разрешающую повторный выбор того же файла. Старые результаты
  сохраняются до действий пользователя.
- Удаление готового файла требует подтверждения с его именем. Повторное удаление
  блокируется на время запроса. При ошибке строка сохраняется с возможностью повторить
  удаление; после успеха обновляются модалка и основной список.
- Порядок строк сохраняется. Загрузки запускаются в порядке добавления. Повтор
  ошибочного файла и действие «Загрузить снова» для отменённого файла ставят существующую
  строку в конец очереди; это не повторный выбор файла через проводник.
- Во время обработки и подтверждения отмена недоступна, соответствующая стадия явно
  показана. Во время подготовки, передачи и ожидания в очереди отмена доступна.
- Повтор загрузки через сервер после потери ответа не должен создавать второй файл.
  В объём задачи входит серверная поддержка этой гарантии.
- При отказе сервера из-за общего лимита активных составных загрузок показывается
  ошибка конкретного файла с ручным повтором. Автоматическое ожидание свободного
  места не входит в первую версию.
- После завершения активных и ожидающих загрузок можно переключить общий режим.
  Новый режим применяется к ещё не запущенным файлам и следующим попыткам; готовые
  результаты сохраняются.
- Удаление использует существующую серверную семантику, одинаковую для модалки и
  основного списка. Подтверждённое физическое удаление объекта не входит в эту задачу.
- При явном выходе история модалки и выбранные файлы очищаются. При истечении сессии
  строки сохраняются с причиной остановки; после входа возможен ручной повтор.

- Фоновая работа ограничена текущей вкладкой. Восстановление после перезагрузки
  страницы или закрытия вкладки не входит в первую версию. При уходе со страницы
  с незавершёнными загрузками используется стандартное предупреждение браузера.
- Выход при незавершённых загрузках требует подтверждения, после которого активные
  и ожидающие операции отменяются. Потеря сессии останавливает очередь с объяснением
  причины. После входа автоматического запуска нет.
- Превышение известного клиенту лимита серверного режима показывается в строке
  соответствующего файла и не блокирует запуск остальных. Сервер проверяет лимит
  независимо от клиентской проверки.
- В строке сохраняются стадия, прогресс, результат и текст ошибки. Над списком
  показываются количества загружающихся, ожидающих, готовых, отменённых файлов и
  файлов с ошибкой. Успех показывается только после ответа сервера.
- Обновление основного списка сохраняет каталог, поиск, сортировку и страницу.
  Файл виден сразу, только если соответствует текущему представлению.
- Повтор одной операции не создаёт второй файл в обоих режимах, включая потерю
  ответа на загрузку через сервер и резервирование прямой загрузки. Гарантия сохраняется
  после перезапуска сервера. Её серверная поддержка входит в объём задачи.
- Новый выбор в новой итерации является отдельной операцией, которой разрешено
  создать ещё один файл. Клиентская проверка имени и размера не заменяет серверную
  гарантию безопасного повтора.
- Повтор старой операции после удаления готового файла не создаёт его заново.
- Если результат неизвестен, показывается «Не удалось выяснить результат». При повторе
  сначала выясняется результат исходной операции; если файл уже готов, показывается
  успех. Пока результат неизвестен, режим этой строки менять нельзя. После подтверждённой
  неудачи можно повторить передачу в другом режиме.
- Обработка, подтверждение и завершение отмены занимают одно из трёх мест до
  окончательного результата. Во время отмены показывается «Отменяем». Следующий
  файл запускается после фактического освобождения места.
- Успешное удаление из основного списка убирает соответствующую строку модалки;
  удаление из модалки обновляет основной список. До окончания текущей итерации
  запрет повторного выбора удалённого файла сохраняется.
- Выход прекращает запуск ожидающих файлов и прерывает операции, которые ещё можно
  прервать. Уже начатая серверная обработка или подтверждение могут завершиться;
  поздние ответы не должны восстанавливать очищенный интерфейс после выхода.

## Требуемые комментарии в коде

По явному указанию пользователя для двух мест сделано исключение из общего запрета
комментариев в `AGENTS.md`. Комментарии пишутся по-русски.

- В обработке ограничения активных составных загрузок: ручной повтор выбран для
  первой версии; решение можно улучшить автоматическим ожиданием свободного места.
- В операции удаления: «Сервер скрывает файл из списка, пытается удалить и возвращает
  успех даже при сбое хранилища».

## Факты текущей реализации

- `useUpload` хранит одно общее состояние и один контроллер отмены на уровне модуля.
  Несколько вызовов composable возвращают одно и то же состояние.
- Сервер уже принимает независимые запросы для отдельных файлов; пакетный запрос
  для выбора нескольких файлов не требуется.
- Большой файл может отправляться частями параллельно. По умолчанию сервер разрешает
  четыре одновременные части одного файла, поэтому три файла могут отправлять
  до двенадцати частей одновременно.
- Прогресс передачи в 100% не означает готовность файла: после передачи требуется
  обработка или подтверждение.
- Подтверждение идемпотентно. Если оно завершилось ошибкой, байты файла могут уже
  находиться в хранилище; новая загрузка с новым резервированием может создать дубликат.
- Текущая отмена предусмотрена до обработки или подтверждения. В серверном режиме
  стадия отправки сейчас не устанавливается, из-за чего кнопка отмены недоступна
  во время отправки.
- Основной список учитывает каталог, поиск, сортировку и страницу. Его обновление
  не гарантирует видимость файла, который не подходит под текущие параметры.
- Удаление сначала скрывает строку метаданных, затем удаляет объект. Ошибка удаления
  объекта сейчас только записывается в серверный лог; API всё равно сообщает успех.
  Повторное удаление возвращает `FILE_NOT_FOUND`, которое текущий клиент считает
  успешным результатом «уже удалён».
- Загрузка через сервер не имеет идемпотентности. Если тело уже принято, сервер может
  сохранить файл после разрыва связи с клиентом. Повтор запроса при потерянном ответе
  может создать дубликат, даже если клиентская проверка повторного выбора сработала.
- Текущая уборка не обходит готовые объекты, оставшиеся после неудачного удаления.
  Поэтому существующее удаление не гарантирует последующее физическое удаление
  такого объекта уборкой.

## Проверка реализации

1. Выбор пяти файлов не отправляет запросы до кнопки запуска; одновременно активны
   не более трёх файлов, включая обработку и подтверждение.
2. Прогресс и отмена одного файла не меняют другие. Завершение отмены освобождает
   место ровно один раз, после окончания активной операции.
3. Закрытие и повторное открытие модалки сохраняют работу и результаты; завершение
   всех файлов не закрывает её автоматически.
4. Дополнительный выбор дополняет список и требует нового явного запуска.
5. Повторный выбор по полному имени и размеру запрещён до конца итерации, включая
   удалённые строки. В новой итерации тот же выбор разрешён.
6. Ошибка одного файла и превышение лимита не мешают допустимым файлам; ручной повтор
   становится в конец очереди. Изменение режима не меняет запущенные операции.
7. Потеря ответа, конкурентные повторы и перезапуск сервера не создают второй файл
   одной операции в обоих режимах. Новая операция может создать другой файл.
8. Ошибка подтверждения повторяет подтверждение. Неизвестный результат сначала
   выясняется; смена режима этой строки до выяснения недоступна.
9. Повтор удалённой успешной операции не воссоздаёт файл. Удаление с подтверждением
   синхронизирует основной список и модалку; ошибка API сохраняет строку.
10. Каждый успех обновляет список без сброса навигации, поиска, сортировки и страницы;
    близкие завершения не теряют результаты обновления.
11. Выход очищает историю и прекращает очередь. Истечение сессии сохраняет строки
    и требует ручного повтора после входа; поздние ответы не восстанавливают очищенное
    состояние после выхода.
12. Прогресс 100% до подтверждения не показывается как успех; оба согласованных
    комментария присутствуют в соответствующих местах кода.

После реализации выполнить общую проверку `npm run check`; проверку устойчивости
серверной идентичности и конкурентных повторов включить в проверки PostgreSQL.
