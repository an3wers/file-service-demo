# Модуль email-уведомлений

Статус: план подтверждён пользователем. Реализация ещё не начата.

Спецификация: [GitHub Issue #45](https://github.com/an3wers/file-service-demo/issues/45)
с меткой `ready-for-agent`. Исходная заявка:
[#27](https://github.com/an3wers/file-service-demo/issues/27).

## Согласовано

- В `server/` нужен базовый модуль `notification`: другие модули передают ему получателя,
  тему и содержимое письма. Привязка к конкретному событию в первый этап не входит.
- Первая версия выполняет одну попытку отправки, ожидает ответ SMTP и возвращает результат
  или ошибку вызывающему коду. Сохранения заданий, фоновой очереди и автоматических повторов
  пока нет; незавершённая отправка при аварии процесса может потеряться.
- Для ручных проверок на разработке и в проде используется Gmail SMTP. В перспективе
  возможен другой SMTP-сервер.
- Автоматические тесты используют подмену почтового транспорта, не обращаются к Gmail
  и не отправляют настоящие письма.
- Один вызов отправляет одно письмо одному явно указанному email. Отправитель задаётся
  конфигурацией; нескольких получателей, CC и BCC в первой версии нет.
- Вызывающий код передаёт готовые тему, обязательный текст и необязательную HTML-версию.
  Шаблоны, вложения и подготовка приветственного письма пока не входят в модуль.
- Уведомления можно явно выключить: тогда SMTP-настройки не обязательны и остальной сервер
  продолжает работать. Отправка через выключенный модуль возвращает явную ошибку.
  При включённых уведомлениях SMTP-настройки обязательны.
- Для ручной проверки нужна CLI-команда, принимающая получателя и отправляющая тестовое
  письмо. HTTP-эндпоинт отправки не нужен.
- Успех означает принятие письма SMTP-сервером, результат — `{ messageId }`. Доставка в ящик
  получателя и прочтение не отслеживаются. При обрыве соединения или таймауте результат может
  быть неизвестен: ошибка не доказывает, что сервер не принял письмо. Повторный вызов может
  создать дубль; дедупликации в первой версии нет.
- Ошибки различают некорректное письмо, выключенные уведомления и сбой отправки. Детали
  почтовой библиотеки не входят в публичный контракт.
- В Gmail используется полный email и пароль приложения Google, без OAuth2. Пароль приложения
  требует включённой двухэтапной проверки и должен быть доступен для выбранного аккаунта.
- SMTP-хост, порт, режим TLS и учётные данные задаются конфигурацией. Поддерживаются TLS
  с начала соединения (Gmail: `smtp.gmail.com:465`) и обязательный STARTTLS (порт 587).
  Проверка сертификатов включена; переход к незашифрованному соединению не допускается.
- При запуске проверяется конфигурация, сетевое соединение открывается только при отправке.
  SMTP не входит в readiness; его недоступность не останавливает сервер.
- Настраиваемые таймауты по умолчанию: соединение — 10 секунд, приветствие SMTP — 10 секунд,
  бездействие соединения — 30 секунд. Это отдельные ограничения, не общий срок отправки.

## Будущий сценарий

Планируется регистрация пользователей с отправкой писем новым пользователям и взаимодействием
модулей через RabbitMQ. Эти возможности не входят в текущий этап. Текущий `auth` работает
с единственным пользователем из окружения и не хранит email; регистрация потребует отдельного
пересмотра [ADR-0007](../adr/0007-autentifikatsiya-polzovatelya-iz-okruzheniya.md).

## План реализации

### Граница и контракт

Модуль размещается в `server/src/modules/notification/`, доступ снаружи — через `index.ts`.
Направление зависимостей следует существующей структуре модулей: сценарий отправки зависит
от внутреннего порта почтового транспорта; SMTP-адаптер реализует порт через Nodemailer.
Типы Nodemailer и SMTP-настройки не попадают в аргументы метода отправки.

Фасад предоставляет `sendEmail({ to, subject, text, html? }): Promise<{ messageId: string }>`.
`to` — один email без списка адресов, `subject` и `text` — непустые строки, `html` —
необязательная непустая строка. Модуль проверяет входные данные до обращения к транспорту;
проверка формата email не подтверждает существование почтового ящика.

Коды публичных ошибок:

| Код                     | Значение                                                   |
| ----------------------- | ---------------------------------------------------------- |
| `INVALID_EMAIL_MESSAGE` | Некорректный получатель или содержимое письма              |
| `NOTIFICATION_DISABLED` | Уведомления явно выключены                                 |
| `EMAIL_SEND_FAILED`     | SMTP отклонил отправку, произошёл сетевой сбой или таймаут |

Проверяется принятие единственного получателя транспортом; одного наличия `messageId`
недостаточно. Результаты библиотеки преобразуются внутри адаптера. Автоматических повторов
и пула SMTP-соединений нет. Создание модуля не открывает сетевое соединение; SMTP-соединение
обслуживает одну попытку отправки.

Сборка SMTP-реализации доступна из `composition.ts` и используется CLI. Текущие `auth` и `files`
не вызывают отправку: конкретных событий первой версии пока нет. Будущий адаптер RabbitMQ
сможет вызывать тот же фасад; подтверждение сообщений брокера, повторы и дедупликация
потребуют отдельного проектирования.

### Конфигурация и ручная проверка

Планируемые переменные:

| Переменная                   | Значение                                                          |
| ---------------------------- | ----------------------------------------------------------------- |
| `NOTIFICATION_ENABLED`       | По умолчанию `false`                                              |
| `SMTP_HOST`                  | Хост SMTP, обязателен при включённых уведомлениях                 |
| `SMTP_PORT`                  | Порт SMTP, обязателен при включённых уведомлениях                 |
| `SMTP_TLS_MODE`              | `implicit` или `starttls`, обязателен при включённых уведомлениях |
| `SMTP_USER`                  | Пользователь SMTP, обязателен при включённых уведомлениях         |
| `SMTP_PASSWORD`              | Пароль SMTP; для Gmail — пароль приложения                        |
| `SMTP_FROM`                  | Email отправителя, разрешённый выбранным SMTP-сервером            |
| `SMTP_CONNECTION_TIMEOUT_MS` | По умолчанию `10000`                                              |
| `SMTP_GREETING_TIMEOUT_MS`   | По умолчанию `10000`                                              |
| `SMTP_SOCKET_TIMEOUT_MS`     | По умолчанию `30000`                                              |

`SMTP_PASSWORD` и `SMTP_FROM` также обязательны при включённых уведомлениях. Все переменные
проходят через `config.ts`, `.env.example` и таблицу `server/README.md`. Таймауты — положительные
числа в миллисекундах, порт — целое число от 1 до 65535. Настройки Gmail приводятся как пример;
в коде адаптера привязки к Google нет.

CLI: `npm run notification:test -w server -- --to recipient@example.com`. Команда отправляет
одно письмо с фиксированными тестовыми темой и текстом через ту же сборку модуля, ожидает
результат и завершается ненулевым кодом при ошибке. Она не запускает HTTP-сервер и не требует
сетевого подключения к БД или объектному хранилищу. При выключенных уведомлениях отправки нет,
команда завершается с ошибкой. Пароль берётся только из конфигурации, не из аргументов команды.

Логи используют существующий `logger`; пароль SMTP и содержимое письма в логи не попадают.
Постоянного журнала отправок, таблиц уведомлений и миграций не требуется.

### Проверки готовности

- Валидное письмо передаётся транспорту с отправителем из конфигурации, успех возвращает
  `messageId`; необязательная HTML-версия передаётся вместе с текстом.
- Некорректный получатель, пустая тема или текст отклоняются до вызова транспорта.
- При выключенных уведомлениях транспорт не вызывается, возвращается явная ошибка.
- Отказ получателя, сбой SMTP и таймаут преобразуются в ошибку отправки без повторной попытки.
- SMTP-адаптер корректно собирает TLS/STARTTLS и таймауты, а результаты библиотеки не выходят
  за его границу; это проверяется подменой библиотеки без реальной сети.
- Выключенная почта допускает отсутствие SMTP-настроек; включённая требует корректных
  обязательных значений. Проверка конфигурации не обращается к SMTP.
- CLI разбирает получателя, ожидает отправку и возвращает подходящий код завершения.
- Автотесты не используют реальные учётные данные и не отправляют письма. Имена тестов —
  на русском языке. После реализации выполняется корневой `npm run check`.
- Реальная проверка Gmail выполняется отдельно вручную через CLI после настройки аккаунта.
