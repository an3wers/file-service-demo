# Аутентификация: один пользователь из окружения, JWT без таблицы токенов

API-ключ в бандле клиента заменён входом по логину и паролю. Пользователь один, его задают
`LOGIN_USER_APP` и `PASSWORD_USER_APP`; при старте сервер заводит для него строку в `users` и
держит её в согласии с окружением. Вход выдаёт короткий токен доступа (JWT, заголовок
`Authorization: Bearer`) и долгий токен обновления (JWT в httpOnly-cookie с `Path=/api/auth`).
Отозвать токены можно только все сразу — через версию, записанную в строке пользователя.

## Почему именно так

- **Окружение — источник истины, строка — его отражение.** Смена пароля в `.env` при
  рестарте перехеширует его и поднимает версию, то есть завершает все сессии. Смена логина не
  удаляет старую строку, но войти и продлить сессию может только пользователь с логином из
  окружения: иначе прежний логин остался бы рабочим незаметно для того, кто правил `.env`.
- **Токен обновления в cookie, токен доступа — нет.** Клиент ходит на `/api` с того же
  origin (vite-прокси, nginx), поэтому cookie ничего не стоит, а долгий токен не достаётся
  XSS. Токен доступа живёт в памяти клиента и уходит заголовком: cookie на каждом запросе
  превратила бы все изменяющие эндпоинты в вопрос о CSRF.
- **Версия вместо таблицы токенов.** Таблица с хешами, ротацией и детектором повторного
  использования — правильнее, но не «просто». Версия даёт единственный нужный рубильник —
  отзыв сессий при смене пароля — ценой одного чтения строки на продление.
- **Токен доступа проверяется без базы.** Файловые запросы не платят за аутентификацию
  запросом в БД; за это после отзыва или смены логина токен доступа живёт до своего
  истечения (`JWT_ACCESS_TTL_MINUTES`).
- **`scrypt` из `node:crypto`.** Без нативной сборки в slim-образе и без новой зависимости.

## Следствия

- Флаг `Secure` у cookie берётся из конфигурации (`COOKIE_SECURE`): развёртывание по
  `docs/deploy.md` работает по HTTP, и браузер молча выбросил бы secure-cookie.
- Выход очищает cookie в одном браузере и ничего не отзывает.
- Файлы остаются без владельца. Таблица `users` допускает много строк, но это не задел на
  многопользовательский режим: владение файлами — отдельное решение.
- Строку пользователя создаёт старт сервера, а таблицу — миграция; без применённой
  миграции сервер не стартует.
