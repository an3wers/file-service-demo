# Состояние файла — сумма типов, а не набор полей

Файл живёт в коде как сумма четырёх состояний — зарезервирован, живая составная загрузка,
готов, неудался, — и данные, которые есть только в одном из них, существуют только внутри него:
план и идентификатор загрузки принадлежат живой составной загрузке, размер и ETag — готовому
файлу. Форма строки таблицы остаётся формой строки таблицы и дальше адаптера хранения
не выходит.

## Почему это не очевидно

Строка `files` отлично описывает файл: `status`, `upload_id`, `size_bytes`, `part_size`,
`part_count` — всё на месте, тип выводится из схемы бесплатно, и именно так и было написано.
Мапперы между строкой и сущностью выглядят как работа ради работы.

## Цена альтернативы

Пять независимых полей дают комбинаций больше, чем состояний: живая загрузка без плана,
готовый файл с идентификатором загрузки, неудавшийся с размером. Настоящих из них четыре,
а тип разрешает все. Разница выплачивается там, где эти поля читают: каждый потребитель
проверяет их по-своему (`upload_id && status === "pending"` в одном месте, три `!== null`
в другом), и каждая такая проверка — это повторённое знание о том, какие сочетания законны.
Невозможное сочетание при этом приходится обрабатывать: [ADR-0003](./0003-plan-zhivoy-sostavnoy-zagruzki-obyazatelen.md)
запретил его в базе и потребовал поднимать внутреннюю ошибку вместо догадки — то есть ветку,
в которую не попасть ни одним путём кода, но которую надо написать и читать.

Вторая цена — зависимость: пока сущность и есть строка, слой правил знает `snake_case`,
`Date` из драйвера и `deleted_at`. Любое изменение схемы становится изменением правил.

## Следствия

- Проверка «сочетание законно» остаётся ровно одна и живёт в конструкторах сущности; адаптер
  хранения подаёт им сырую строку. Невозможная строка по-прежнему поднимает внутреннюю ошибку —
  ADR-0003 в силе, включая ограничение `files_multipart_plan_check`, — но теперь в одном месте
  на границе, а не всюду, где поля читают.
- `deleted_at` в сущность не едет: удалённая строка — не состояние файла, а его отсутствие.
  Мягкое удаление остаётся свойством хранилища строк.
- Появляется маппинг строка → сущность и сущность → ответ API. Это цена, и она принята
  осознанно: взамен слой правил перестаёт зависеть от схемы таблицы.
