# Повтор операции загрузки не создаёт второй файл

При потере ответа клиент не знает, сохранился ли файл, поэтому повтор полной загрузки
с новым резервированием может создать дубликат. Сервис должен сохранять устойчивую
идентичность операции загрузки и возвращать её прежний результат при повторе в обоих
режимах, включая потерю ответа при резервировании и перезапуск сервера. Выбрана
серверная гарантия вместо одной клиентской проверки имени и размера, поскольку
клиент не может установить результат запроса по факту разрыва соединения.

## Следствия

- Новый выбор файла в новой итерации создаёт отдельную операцию; одинаковые файлы
  разных операций допустимы.
- Повтор подтверждения относится к существующему файлу. При неизвестном результате
  сначала выясняется исходная операция, затем допускается новая передача, если
  неудача подтверждена.
- Повтор после удаления успешного результата не воссоздаёт файл.
- В задачу параллельной загрузки входит изменение серверного контракта и устойчивого
  хранения идентичности операции, а не только клиентской очереди.
- Это решение не меняет доменные состояния файла и правило неизменности плана
  составной загрузки из ADR-0003 и ADR-0004.
